# Runtime and save isolation

## Ownership

`lab.toml` is generated by `scripts/locate.py` and ignored; `lab.example.toml` documents each field. The locator scans native and Flatpak Steam roots and every library in `libraryfolders.vdf`, then records the owned installation, Proton, prefix seed, canonical Steam prefix, Steam client, writable lab state, and the pinned executable hash. `locate.py` sets `seed_prefix` to the canonical prefix; it is only a copy source for the disposable prefix. `prepare` copies the shipping executable, DLLs, qualified loader settings, and loader support files. Engine, content, and plugins resolve to the owned assets through symlinks. The private Win64 directory owns the harness and logs. No installer writes to the original game directory.

The game runs under `gr2-groundtruth-game.service`. Its Bubblewrap mount namespace exposes the canonical app prefix, original game tree, and Steam userdata read-only. Devices retain their device-mount semantics, including `/dev/urandom`. This is save protection, not a filesystem or network sandbox for untrusted mods.

`gr2-groundtruth.service` owns a GPU-backed headless Gamescope display at 1280x720, 60 Hz. Xdotool uses the display published by that service and selects the exact game window. The optional Steam client has a separate service/display. Game shutdown leaves an existing Steam client running. Cold client startup waits for a newly appended Steam login acknowledgement; process existence alone was insufficient in a failed launch probe.

Proton uses `runinprefix`, DX11, X11, and `WINEDLLOVERRIDES=dwmapi=n,b;dxgi,d3d11=n`. The copied UE4SS settings retain `HookCallFunctionByNameWithArguments=0`, the prior isolated startup fix. The harness installs only its own mod in the staged load order. It does not enable broad native function hooks.

## Saves

The canonical source is `<canonical_prefix>/pfx/drive_c/users/steamuser/AppData/Local/Ghostrunner2/Saved`. Each launch copies that directory into the lab prefix. SaveGames files are hashed before a launch and checked after experiments and shutdown. A previous hash mismatch blocks refreshing the disposable copy. The destination must resolve inside the lab prefix; a save-directory symlink escaping it is rejected before deletion.

The copy retains the campaign's progression, graphics preferences, and motherboard loadout. The canonical files supply initial data only. All game save writes go to the lab prefix or private install-side Saved directory. Direct Proton launch avoids Steam's normal app-launch cloud-sync sequence. An independently running Steam client or human can still modify host files, so hash verification is also required. Experiments run while the user's canonical GR2 session is closed.

`reset-saves` restores the disposable copy while stopped. `reset` is a lighter game-side reset: it removes explicitly spawned test actors, stops player velocity, teleports to the current area's start, and calls native SetStamina with 100. It does not reset every latent Blueprint state or game clock. A fresh launch is the stronger experiment boundary.

## Game commands

Invoke as `python3 scripts/lab.py cmd <command> [arguments]`.

| Command | Result |
| --- | --- |
| `status` | Loaded worlds, possessed Jack identity, actor count, recording status |
| `travel /Game/...` | Unreal OpenLevel request; use status to establish completed possession |
| `build` | Replace harness geometry and teleport to runway |
| `teleport <area>` | Stop movement, place Jack at the area's start, face +X |
| `pose x y z [yaw] [pitch]` | Place Jack at exact absolute centimeter coordinates |
| `reset` | Remove spawned enemies/targets and reset player position/velocity/stamina |
| `observe` | One position, velocity, acceleration, clock, stamina, and state observation |
| `physics` | Simulated cube and scripted platform positions/velocity |
| `upgrades` | Current motherboard sockets, raw upgrade IDs, boost flags, core level |
| `set_stamina value` | Native setter, subject to native clamping and regeneration |
| `spawn pistol\|shinobi\|grapple [x] [y] [z]` | Spawn native cooked Blueprint; y is relative to current area |
| `record_start`, `record_stop` | Append polled observations to staged `gt.telemetry.jsonl` |
| `inspect ClassName` | Bounded object identities for reverse engineering |
| `functions /Script/...` | Reflected function identities, without invoking them |

Areas and dimensions are authored in `harness/Scripts/areas.lua`. All geometry positions and lengths use centimeters. Starts face +X. Areas occupy separate Y lanes above the stock world. Runway edge markers occur every 1000 cm. Grapple fixtures are at absolute X=0 and 2000, lane Y=40000, Z=11000 and 12000. Gap platform heights are explicit in the geometry definitions. `physics` includes a native simulated cube and a sinusoidal platform with 500 cm amplitude and a four-world-second period.

## Telemetry

Sampling requests run every 50 ms and coalesce to one pending game-thread callback. Duplicate game-clock samples are omitted. A sampling failure stops recording and appears in `status` and `record_stop` as `sampling_error`; rebuild after inspecting the failure. JSONL includes world and pawn identity, position in cm, control rotation in degrees, velocity in cm/s, native CharacterMovement acceleration, movement modes, selected declared player/stamina fields, and game/audio clocks. `observed_acceleration` is a finite difference of sampled velocity; it is a separate measurement from native acceleration.

The serializer and field-selection technique grew out of earlier polling-recorder work. UObject identity is copied without traversing arbitrary object members. Upgrade struct/array capture is bounded and includes truncation flags. Named experiment files include only their own telemetry slice and a loadout snapshot. `lab.py key <keysym> <seconds>` sends held keys and chords; `lab.py mouse dx dy` sends relative pointer motion to the focused private game window. Physical input comes from Xdotool; scheduling is wall-clock based and is not a deterministic physics tick driver.

## Limits

- Standalone custom cooked travel and streamed-sublevel replacement remain unimplemented. A qualified stock test world initializes native systems; UE4SS supplies custom areas.
- Runtime spawned geometry has no new navmesh. Spawned enemy identity is qualified; full enemy navigation/combat behavior is not.
- Grapple targets spawn, but target selection and complete grapple traversal need dedicated qualification.
- Reset is partial. Death, cooldowns, latent abilities, upgrades, enemy registration side effects, and moving-platform phase can require a fresh launch.
- Arbitrary `set_upgrades` is not exposed. The copied save supplies the loadout; `upgrades` records it. Native registration alone would not prove a coherent motherboard or save state.
- The scripted moving platform is harness-driven geometry. It is not the stock GR2 moving-platform Blueprint.
- Polling can miss short states and events. No exact native event order, tick identity, frame pacing, or full game-system initialization parity is claimed.
